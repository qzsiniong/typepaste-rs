## 整体架构（双向闭环）

### 2\.1 正向通道（本机 → VDI）

本机 Rust 发送端：
 文件 → 智能压缩 \(zstd\) → 分片 → 协议封装 → **模拟物理键盘按键投递**

VDI 浏览器接收端：
`keydown`/`keyup` 全局监听 → 流式拼接帧 → 解码解压 → 分片落盘缓存

### 2\.2 反向反馈通道（VDI → 本机）

VDI 网页：
 每分片处理完成 → 生成状态 JSON → **固定位置渲染二维码**

本机 Rust 接收反馈：

定时截取固定屏幕区域 → 二维码解码 → 获取状态 → 驱动状态机（下一帧 / 重传 / 暂停 / 结束）

### 2\.3 整体闭环

**发送分片 → 远端处理 → 二维码返回结果 → 本机决策**
 完全可靠、完全自动化、无人工干预。

## VDI 网页接收端设计（核心）

### 3\.1 页面能力

1. **全局键盘监听**

- 不需要输入框、不需要聚焦控件

- `document.addEventListener('keypress')` 全局捕获所有键入

- 纯净流接收，无输入法干扰、无焦点依赖

2. **流式协议解析**
 自定义二进制文本帧协议（防粘包、防断流）

**帧格式（固定）**

```Plain Text
[STX 0x02] 帧数据 [ETX 0x03]
```

单帧内部结构：

```Plain Text
seq|total|rawSize|zstdFlag|md5Chunk|payload
```

所有字段 `|` 分割，可无损流式解析。

3. **自动落盘（无下载弹窗）**
 使用浏览器 **FileSystemFileHandle API**

- 用户一次授权目录

- JS 直接逐分片写入文件

- 传输完成即为完整文件，**无需手动保存、无需下载**

4. **固定二维码反馈区域**
 页面角落固定 DOM，固定像素尺寸：

- 只输出极小 JSON 状态

```JSON
{"seq":0,"status":"OK","md5":"xxx","err":""}
```

状态枚举：

- `OK`：分片正确，继续下一片

- `RETRY`：分片校验失败，请求重传

- `FINISH`：全部传输完成

- `ERROR`：致命错误终止

5. **页面焦点上报机制**
 网页实时监听 `window.blur / focus`

- 失焦：二维码输出 `PAUSE`

- 聚焦：二维码输出 `READY`

本机读取二维码状态，自动暂停 / 恢复传输。

## 协议详细定义

### 5\.1 压缩策略

- 文本 / 程序：zstd\-6 高压缩

- 普通文件：zstd\-3 平衡

- 高熵文件 \(zip/jpg/7z\)：**跳过压缩**

### 5\.2 分片大小

默认：**4KB 压缩后分片**
 兼顾：速度、重传代价、二维码反馈延迟

### 5\.3 完整帧示例

```Plain Text
\x020|128|4096000|1|xxxx|base64payload\x03
```

### 5\.4 反馈二维码数据结构（极简）

```TypeScript
interface Feedback {
  seq: number;        // 当前分片号
  status: OK|RETRY|FINISH|PAUSE|ERROR;
  md5: string;       // 本分片md5
  err?: string;
}
```

数据极小，**二维码 100% 稳定识别**，不受 VDI 轻微压缩影响。

## 全自动传输流程（完整闭环）

1. **前置准备（一次性）**

    - VDI 打开本地 `receiver.html`

    - 浏览器授权文件写入目录

2. **本机启动传输**

    - 等待用户鼠标点击 VDI 浏览器窗口激活焦点

    - 读取二维码状态确认 `READY`

3. **循环传输**

    - 发送当前分片完整协议帧

    - 停止发送 → 截屏读取二维码状态

    - OK → md5验证数据完整性 seq\+1 下一片

    - RETRY → 重传当前片

    - PAUSE → 休眠轮询等待聚焦

    - FINISH → 结束传输、校验整体 MD5

4. **最终结果**

- VDI 磁盘**直接生成完整文件**

- 全程零人工操作
