# Web 传输场景测试用例

> 基于 `src/web.rs`、`assets/receiver.html`、`src/qr.rs`、`src/cli.rs` 的完整实现编写。
> 适用于真实环境（macOS + VDI 浏览器）手动测试。

## 测试环境准备

| 项目  | 要求                                                                   |
| --- | -------------------------------------------------------------------- |
| 本机  | macOS，已编译 `cargo build --release`                                    |
| VDI | Chrome/Edge 浏览器，支持 FileSystem API                                    |
| 权限  | 本机终端已获辅助功能授权                                                         |
| 依赖  | Tesseract/leptonica（二维码解码）                                           |
| 部署  | `./target/release/typepaste-rs --deploy-receiver /tmp/receiver.html` |

***

## 二、基本传输流程

### TC-010 小文件传输（单片，不压缩）

| 项        | 内容                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------- |
| **前置**   | receiver.html 已授权目录，本机执行 `typepaste-rs --web <file>`                                               |
| **测试文件** | `echo "hello web" > /tmp/small.txt`（11 字节，纯 ASCII）                                                 |
| **步骤**   | `typepaste-rs --web /tmp/small.txt --delay 5`                                                      |
| **预期**   | <br />                                                                                             |
| 发送端      | 倒计时后等待 READY → 发送 PROBE → 收到 PROBE 位图（空）→ 发送 1 片 → 收到 FINISH + md5 → 显示「传输完成，整文件 MD5 校验通过 ✓」+ 耗时统计 |
| 接收端      | 状态栏显示「传输完成: small.txt」；数据面板显示分片信息、hex dump、MD5、耗时                                                  |
| 文件验证     | VDI 目录中 `small.txt` 存在，`md5sum` 与本机一致                                                              |

### TC-011 文本文件传输（启用 zstd 压缩）

| 项        | 内容                                                              |
| -------- | --------------------------------------------------------------- |
| **测试文件** | `python3 -c "print('hello '*2000)" > /tmp/text.txt`（\~10KB 高重复） |
| **步骤**   | `typepaste-rs --web /tmp/text.txt --delay 5`                    |
| **预期**   | 发送端日志显示「zstd 启用」；接收端面板显示 `zstd` 标记；最终文件 md5 匹配                  |

### TC-012 二进制文件传输（多片，高熵不压缩）

| 项        | 内容                                                              |
| -------- | --------------------------------------------------------------- |
| **测试文件** | `head -c 10240 /dev/urandom > /tmp/random.bin`（10KB 随机数据）       |
| **步骤**   | `typepaste-rs --web /tmp/random.bin --web-chunk 1024 --delay 5` |
| **预期**   | 发送端日志显示「高熵跳过压缩」；分片数 ≥ 10；每片逐帧输入后收到 OK；最后一片收到 FINISH             |
| **验证**   | VDI 中 `random.bin` 的 md5 与本机一致                                  |

### TC-013 大文件多片传输

| 项        | 内容                                                                  |
| -------- | ------------------------------------------------------------------- |
| **测试文件** | `head -c 102400 /dev/urandom > /tmp/large.bin`（100KB）               |
| **步骤**   | `typepaste-rs --web /tmp/large.bin --web-chunk 4096 --delay 5`      |
| **预期**   | 进度条正常递增；发送端显示 `p1 >>> md5=...` \~ `p25 >>> md5=...`；完成后显示 KB/s 速率统计 |

### TC-014 空文件传输

| 项        | 内容                                                                            |
| -------- | ----------------------------------------------------------------------------- |
| **测试文件** | `touch /tmp/empty.bin`（0 字节）                                                  |
| **步骤**   | `typepaste-rs --web /tmp/empty.bin --delay 5`                                 |
| **预期**   | 分片数为 1；传输完成后 VDI 中 `empty.bin` 大小为 0；md5 = `d41d8cd98f00b204e9800998ecf8427e` |

### TC-015 中文文件名传输

| 项        | 内容                                             |
| -------- | ---------------------------------------------- |
| **测试文件** | `echo "test" > "/tmp/测试文件.txt"`                |
| **步骤**   | `typepaste-rs --web "/tmp/测试文件.txt" --delay 5` |
| **预期**   | VDI 中文件名为 `测试文件.txt`；二维码反馈中无 UTF-8 编码错误；md5 匹配 |

### TC-016 文件名含路径分隔符（仅取 basename）

| 项        | 内容                                               |
| -------- | ------------------------------------------------ |
| **测试文件** | `/tmp/sub/test.txt`                              |

| **预期**   | VDI 中文件名为 `test.txt`（不含目录路径）                     |

## 三、断点续传（PROBE 协商）

### TC-020 首次传输（无已有分片）

| 项      | 内容                                                      |
| ------ | ------------------------------------------------------- |
| **前置** | VDI 保存目录为空                                              |
| **步骤** | 传输一个 5 片文件                                              |
| **预期** | 发送 PROBE 后收到位图为空（`00` 或全 0）；发送端日志无「跳过」；全部 5 片传输后 FINISH |

### TC-021 部分分片已存在（中断后续传）

| 项      | 内容                                   |
| ------ | ------------------------------------ |
| **前置** | 先传输一个 5 片文件，在第 3 片后 Ctrl+C 中断        |
| **步骤** | 再次执行 `typepaste-rs --web <同一文件>`     |
| **预期** | <br />                               |
| PROBE  | 接收端扫描到 `.p1`、`.p2` 已存在，位图反馈含 bit 0,1 |
| 发送端    | 日志显示「断点续传：跳过已存在的 2/5 片」；进度条从 2 开始    |
| 结果     | 只发送片 3-5，完成后 md5 校验通过                |

### TC-022 非连续分片已存在

| 项      | 内容                                                               |
| ------ | ---------------------------------------------------------------- |
| **前置** | VDI 目录中手动保留 `.p1` 和 `.p3`，删除 `.p2`                               |
| **步骤** | 传输同一文件                                                           |
| **预期** | 位图反馈含 bit 0,2（seq 0 和 2）；发送端跳过片 1、3，只发片 2、4、5（1-based）；最终 md5 匹配 |

### TC-023 全部分片已存在

| 项      | 内容                                                                        |
| ------ | ------------------------------------------------------------------------- |
| **前置** | 先完整传输一个文件，保留所有 `.pN` 分片和最终文件                                              |
| **步骤** | 再次传输同一文件                                                                  |
| **预期** | PROBE 后接收端发现分片齐全 → 拼接解压 → FINISH + md5；发送端收到 FINISH 后「全部分片已存在，MD5 校验通过 ✓」 |

### TC-024 完整文件已存在且 md5 匹配

| 项      | 内容                                                                       |
| ------ | ------------------------------------------------------------------------ |
| **前置** | VDI 目录中已有完整文件（md5 正确）                                                    |
| **步骤** | 再次传输同一文件                                                                 |
| **预期** | PROBE 后接收端检测到完整文件 md5 匹配 → 直接 FINISH；发送端「远端已存在完整文件且 MD5 校验通过 ✓」；不发送任何数据帧 |

### TC-025 完整文件已存在但 md5 不匹配

| 项      | 内容                                             |
| ------ | ---------------------------------------------- |
| **前置** | VDI 目录中有同名文件但内容不同（md5 不匹配）                     |
| **步骤** | 传输正确文件                                         |
| **预期** | 接收端检测到文件 md5 不匹配 → 继续扫描分片 → 返回 PROBE 位图；正常传输分片 |

### TC-026 不同文件同名（PROBE md5 不匹配场景）

| 项      | 内容                                                     |
| ------ | ------------------------------------------------------ |
| **前置** | 先传输 `fileA.txt`（5 片），再传输另一个内容不同但同名的 `fileA.txt`        |
| **步骤** | 第二次传输                                                  |
| **预期** | PROBE 中 file\_md5 不同；接收端旧分片 md5 与新分片不同 → RETRY → 发送端重传 |

## 四、错误处理与重试

### TC-030 分片 md5 校验失败（接收端 RETRY）

| 项      | 内容                                                              |
| ------ | --------------------------------------------------------------- |
| **前置** | 正常传输中                                                           |
| **步骤** | 在某片传输过程中模拟数据损坏（如快速切走窗口导致字符丢失）                                   |
| **预期** | 接收端检测到 md5 不匹配 → 反馈 RETRY；发送端日志显示「片 N 未确认（第 1 次重试），重发...」；重发后成功 |

### TC-031 超过最大重试次数

| 项      | 内容                      |
| ------ | ----------------------- |
| **前置** | `--web-max-retry 2`     |
| **步骤** | 持续干扰传输使同一片连续失败 3 次      |
| **预期** | 发送端报错「片 N 重试 3 次仍失败」并退出 |

### TC-032 接收端 ERROR 反馈

| 项      | 内容                                     |
| ------ | -------------------------------------- |
| **前置** | 接收端写入失败（如磁盘满）                          |
| **步骤** | 传输文件                                   |
| **预期** | 接收端反馈 ERROR + 错误信息；发送端报「接收端错误：写入失败」并退出 |

### TC-033 传输中页面刷新（丢失授权）

| 项      | 内容                                                   |
| ------ | ---------------------------------------------------- |
| **前置** | 传输进行到第 3 片                                           |
| **步骤** | 在 VDI 浏览器中刷新 receiver.html 页面                        |
| **预期** | 接收端反馈 UNAUTH；发送端报「接收端未授权保存目录（页面可能已刷新），请重新授权后开始传输」并退出 |

### TC-034 等待 READY 超时

| 项      | 内容                                                             |
| ------ | -------------------------------------------------------------- |
| **前置** | receiver.html 未打开或未授权                                          |
| **步骤** | `typepaste-rs --web /tmp/test.txt --delay 5`，不打开 receiver.html |
| **预期** | 发送端等待 READY，长时间无反馈后报「等待接收端 READY 超时」                           |

### TC-035 ACK 超时重发

| 项      | 内容                                  |
| ------ | ----------------------------------- |
| **前置** | 正常传输中                               |
| **步骤** | 遮挡二维码区域使发送端无法读取反馈                   |
| **预期** | 30 秒后发送端按超时处理 → Ack::Resend → 重发当前片 |

## 五、焦点保护

### TC-040 传输中切换窗口（本机失焦）

| 项      | 内容                                                         |
| ------ | ---------------------------------------------------------- |
| **前置** | 正常传输多片文件中                                                  |
| **步骤** | 帧发送过程中快速 Cmd+Tab 切到其他 App                                  |
| **预期** | <br />                                                     |
| 发送端    | 焦点监视器检测到前台 App 变化 → 1 字符内停止输入 → 日志「检测到窗口失焦，已立即停止输入」→ 等待恢复  |
| 接收端    | 窗口 blur 事件 → 反馈 PAUSE → 数据面板显示「窗口失焦，暂停接收」                  |
| 恢复     | 切回 VDI 窗口 → 接收端 focus 事件 → 反馈 READY → 发送端整帧重发（Ctrl+A 清除半帧） |

### TC-041 传输中页面失焦（VDI 内部失焦）

| 项      | 内容                                                            |
| ------ | ------------------------------------------------------------- |
| **前置** | 正常传输中                                                         |
| **步骤** | 在 VDI 内点击浏览器地址栏或其他非页面区域（页面失焦但 VDI 窗口未切换）                      |
| **预期** | 接收端 blur → PAUSE；发送端二维码检测到 PAUSE → 暂停 → 等待页面重新聚焦 → READY → 重发 |

### TC-042 失焦期间半帧清理

| 项      | 内容                                                                           |
| ------ | ---------------------------------------------------------------------------- |
| **前置** | 正在发送某帧（已输入部分字符）                                                              |
| **步骤** | 切走窗口后再切回                                                                     |
| **预期** | 接收端 focus 时 `liveFrameReset()` 丢弃半帧缓冲；发送端重发时先 Ctrl+A 清除残留；数据面板显示「RESET 丢弃半帧」 |

### TC-043 焦点监视器启动失败

| 项      | 内容                                            |
| ------ | --------------------------------------------- |
| **前置** | 模拟 FocusMonitor 启动失败（如 osascript 不可用）         |
| **步骤** | 正常传输                                          |
| **预期** | 发送端 warn「焦点监视器启动失败」；传输仍可进行，失焦检测退化为二维码兜底（响应较慢） |

### TC-044 PAUSE 超时

| 项      | 内容                  |
| ------ | ------------------- |
| **前置** | 传输中触发 PAUSE         |
| **步骤** | 不切回 VDI 窗口，等待 600 秒 |
| **预期** | 发送端报「等待页面重新聚焦超时」并退出 |

## 七、二维码反馈通道

### TC-060 READY 状态

| 项       | 内容                                                         |
| ------- | ---------------------------------------------------------- |
| **触发**  | 接收端授权目录后 / 页面重新聚焦                                          |
| **二维码** | `{"seq":N,"status":"READY","md5":"","err":""}`（seq 为已接收片数） |
| **发送端** | 识别为 READY，开始/恢复传输                                          |

### TC-061 OK 状态

| 项       | 内容                                                     |
| ------- | ------------------------------------------------------ |
| **触发**  | 分片 md5 校验通过且未到末片                                       |
| **二维码** | `{"seq":N,"status":"OK","md5":"<chunk_md5>","err":""}` |
| **发送端** | 识别为 ACK，发送下一片                                          |

### TC-062 RETRY 状态

| 项       | 内容                                                                   |
| ------- | -------------------------------------------------------------------- |
| **触发**  | 分片 md5 不匹配 / base64 解码失败                                             |
| **二维码** | `{"seq":N,"status":"RETRY","md5":"<expected_md5>","err":"分片md5不匹配"}` |
| **发送端** | 识别为 Resend，重发当前片                                                     |

### TC-063 FINISH 状态

| 项       | 内容                                                        |
| ------- | --------------------------------------------------------- |
| **触发**  | 所有分片到齐，拼接解压后整文件 md5 校验通过                                  |
| **二维码** | `{"seq":N,"status":"FINISH","md5":"<full_md5>","err":""}` |
| **发送端** | 识别为 Finished，比对 md5 后显示「传输完成 ✓」+ 耗时/速率统计                  |

### TC-064 PAUSE 状态

| 项       | 内容                                             |
| ------- | ---------------------------------------------- |
| **触发**  | 接收端窗口 blur                                     |
| **二维码** | `{"seq":N,"status":"PAUSE","md5":"","err":""}` |
| **发送端** | 停止发送，等待 READY 恢复                               |

### TC-065 ERROR 状态

| 项       | 内容                                                   |
| ------- | ---------------------------------------------------- |
| **触发**  | 帧字段不足 / 帧头解析失败 / 写入失败                                |
| **二维码** | `{"seq":N,"status":"ERROR","md5":"","err":"<错误信息>"}` |
| **发送端** | 报错退出                                                 |

### TC-066 UNAUTH 状态

| 项       | 内容                                                     |
| ------- | ------------------------------------------------------ |
| **触发**  | 未授权目录 / 页面刷新后丢失授权                                      |
| **二维码** | `{"seq":0,"status":"UNAUTH","md5":"","err":"未授权保存目录"}` |
| **发送端** | 持续等待，定期提示「等待接收端授权保存目录…」，不计入超时                          |

### TC-067 PROBE 状态

| 项       | 内容                                                           |
| ------- | ------------------------------------------------------------ |
| **触发**  | PROBE 帧后扫描到已有分片                                              |
| **二维码** | `{"seq":-1,"status":"PROBE","md5":"<bitmask_hex>","err":""}` |
| **发送端** | 解析位图，跳过已存在分片                                                 |

### TC-068 中文错误信息二维码

| 项      | 内容                                                                                |
| ------ | --------------------------------------------------------------------------------- |
| **触发** | 错误信息含中文（如「分片md5不匹配」）                                                              |
| **预期** | 二维码使用 UTF-8 编码（`stringToBytesFuncs['UTF-8']`）；本机 rqrr 解码无 `Encoding(Not UTF8)` 错误 |

## 八、接收端数据面板

### TC-070 实时数据滚动显示

| 项      | 内容                                                                          |
| ------ | --------------------------------------------------------------------------- |
| **前置** | 传输进行中                                                                       |
